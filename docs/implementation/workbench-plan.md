# UI 工作台执行计划

本次按八张概念图实现可运行的本地工作台，并接入当前 M0～M7 核心。视觉基准为 1586 × 992，兼顾窄窗口；真实作品内容、状态和按钮可用性来自本地工作区，示例数据仅用于明确标注的离线验收。

## 执行约定

- 在现有单包工程内使用 React、TypeScript、Vite 与 Node.js 本地 HTTP 服务，继续使用 SQLite、现有工作流及统一提交规则。
- 模型调用仍经已有网关与预算；默认不开启外部模型请求，普通测试使用固定响应。真实模型配置在服务器读取，密钥不返回浏览器。
- 浏览器只访问已登记工作区。本地服务校验 Host、Origin、会话令牌、请求大小及输入结构，拒绝任意文件系统访问。
- 候选批准、修改组、锁定、来源确认、历史恢复等操作复用核心服务；缺少数据时展示真实空状态，不用图片或固定文字代替功能。
- 不增加手工编辑模型候选、云同步、多人协作或发布功能。作者仍可手工修改正式稿并创建新版本。
- 每步完成必要验证后更新进度并执行一次本地 Git 提交；当前分支为 main。提交包含对应实现、必要测试与受影响文档。既有设计稿在 P0 一并保存。
- 本轮不创建 Goal，不委派子 Agent。先后顺序如下，发现问题时在当前步骤修复后继续。

## P1 本地接口与后台任务

范围：`src/server/`、`src/application/` 的工作台适配，必要的运行创建通知与字节导入入口，以及接口测试。先提供工作区登记、新建、导入预览与确认、查询、现有业务动作和后台任务入口。

接口决定：稳定工作区 ID；请求携带当前项目版本；长任务返回持久化 runId，浏览器断开不取消任务；轮询读取实际任务状态；显式 unknown 重试沿用原预算；重复启动请求使用相同请求身份复用任务。只读查询不修改核心状态。

验收：有效工作区与固定响应闭环可用；错误 Origin、令牌、路径、超限上传、过期版本和重复请求被正确处理；密钥不出现在接口结果；读操作无模型请求。运行 check、test、build。

提交：`feat: 增加本地工作台接口与持久化任务接入，复用核心提交边界`。

状态：已完成。check、111 项测试和 build 通过；新增 10 项接口与工作流回归覆盖来源、令牌、工作区路径、上传、版本冲突、三章闭环、请求复用、unknown、取消和只读查询。

## P3 规划与章节创作闭环

范围：规划页与章节工作台、正文阅读、计划表单、候选与正式稿切换、证据定位、审稿、修订、作者理由、批准拒绝，以及作者正式稿编辑。

验收：固定响应完成三章规划与逐章生成、审稿、批准；没有计划或前序未批准时不能写下一章；确定冲突禁批；理由、版本与报告绑定由后端最终校验；证据按原始版本定位。切页或刷新不重复模型请求。

提交：`feat: 接入章节规划写作与审稿批准，保留正文证据和版本校验`。

状态：已完成。112 项离线测试、类型检查和构建通过；浏览器完成三章规划、编辑批准、生成、冲突禁批、原文定位、修订、逐章批准与作者保存新版本，刷新不重复启动，未保存导航可取消。修复预填正文的标签绑定和失败审稿导致候选不可读的问题。

提交：`feat: 接入任务恢复预算与模型检查，明确未知请求和费用状态`。

状态：已完成。113 项离线测试、类型检查与构建通过；5 项浏览器流程通过，验证预算应用、探测与只读重放、unknown 显式重试并保留原预算、在途取消和缺失凭据禁用探测。中断状态只读推导，不修改持久化记录。
