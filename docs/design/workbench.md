# UI 工作台功能与概念设计

建议把 novel-engine 做成以章节正文为中心的单用户本地 Web 工作台。作者在同一处查看候选稿、核对审稿证据、提出修订要求并批准正式稿；来源记忆与运行记录为这些决定提供依据。

设计基线为 Git 提交 `c4942e1`。当前产品入口仍是 CLI，本文中的页面、HTTP 接口和浏览器交互属于设计方案。概念图采用虚构作品《雾港来信》，图中的章节、数量、问题与状态均为示例；M0～M7 工程验收和真实创作效果验收继续分开记录。

## 1 产品方向

工作台要让作者随时看清三件事：正在看哪份正文、系统为何提出这个修改、点击按钮后会改变什么。默认打开上次阅读的章节；有待处理候选或中断任务时，在章节和任务入口显示提示。

采用“导航与章节 + 正文 + 审稿与来源”的结构。正文保持主要阅读空间，右侧面板随当前选择显示问题证据、章节目标或上下文。模型的工作用“规划、生成、审稿、修订”表达，不要求作者理解 Agent 名称、调用链和数据库字段。

首版范围是本机单用户、一个工作区内的完整创作流程。多人协作、云同步、自动连载发布、自由 Agent 聊天、任意人物知识图谱和全书自动批准不进入首版。

## 2 页面与功能

| 页面或入口 | 作者可以做什么 | 当前能力依据 | UI 接入阶段 |
| --- | --- | --- | --- |
| 作品入口 | 打开本地工作区、新建作品、预览拆章后导入稿件 | `createWorkspace`、`CommitService.importFile`；最近作品列表与浏览器文件接入需新增 | UI-1 |
| 规划 | 输入创作要求，每批规划 1～20 章；编辑章节目标、人物、视角、约束、事件和目标长度；批准计划 | `CreationWorkflow.plan`、`ProposalService.editPlan/approve` | UI-1 |
| 章节工作台 | 阅读正式稿与候选稿；查看上下文；生成并审稿；按要求修订；批准或拒绝；作者手工修改正式稿 | `write/draft/review/revise`、`ProposalService`、`CommitService.replace` | UI-1 |
| 故事记忆 | 按人物、关系和来源查阅信息；区分事实、误信和计划；确认、纠正、设置别名、查看或重建失效来源 | `MemoryStore`、`MemoryWorkflow`、`buildContext` | UI-2 |
| 局部改稿 | 输入改稿要求，查看覆盖范围和影响；选择修改组、比较正文、保护锁定段落；重新审稿并批准实际选择结果 | `ImpactWorkflow`、`PatchService`、`selectionContext` | UI-3 |
| 任务记录 | 查看步骤、预算和请求状态；取消、恢复；对未知结果显式选择是否重试；只读重放 | `RunStore`、各工作流 `resume`、`replayRun` | UI-1；高级诊断后置 |
| 版本与导出 | 选择项目历史版本，查看章节；导出 Markdown 或 TXT；恢复旧章与撤回改稿时预览变化 | 项目快照、`exportText`、`chapter restore`、`PatchService.undo` | UI-1 基础；UI-3 完整对比 |
| 模型与设置 | 查看脱敏配置、检查环境、设置单次任务请求数与 token 上限、明确触发模型探测 | `loadConfig`、`doctor`、`ProbeWorkflow`、`BudgetSchema` | UI-1 |

作品入口位于左上角，不另设仪表盘首页。最近作品列表仅登记作者主动打开的项目，不扫描本机稿件目录。导入先展示编码、章名、章节数量和重复检测结果，再确认写入；已导入同一路径但内容变化时，转入明确的章节替换流程。

规划编辑针对待批准提案，保存后产生新的提案版本。已批准计划的任意改写和人物独立档案管理没有现成的完整 CRUD，不在 UI 中伪装成已有能力。人物筛选首先从计划、别名和事实中聚合；作者硬约束仍对应现有的字符串列表。

## 3 章节工作台

### 布局

- 左侧：作品入口、功能导航和章节列表。章节状态可显示“待规划、待生成、有候选、待修订、待批准”；正式稿存在与否单独显示，避免一个状态覆盖所有含义。
- 中间：章名、正式稿与候选稿切换、正文、版本入口。长文按段阅读，点击问题高亮对应原句；候选稿始终显示“未批准”。
- 右侧：审稿、本章计划、上下文三个页签。审稿优先展示确定冲突，然后是待核查与风格建议。
- 底部：当前任务步骤及下一步。生成成功、审稿完成、作者批准分别呈现，不合并为一个“完成”。

目标桌面宽度为 1440～1920 px。导航约 220 px，右栏约 360 px，中间自适应；正文行宽控制在约 28～38 个中文字符。低于 1280 px 时右栏改为可打开的抽屉，章节列表可折叠；首版针对桌面长文工作，不承诺手机完整编辑。

### 从规划到正式稿

1. 作者批准本批章节计划。没有已批准计划，或前序章节尚未接受时，生成按钮显示具体原因。
2. 点击“生成并审稿”前可查看上下文来源及任务预算。默认走 `workflow write` 的完整链路；高级选项才提供“仅生成候选”。
3. 系统保存候选、审稿报告和事实提取结果。界面停在候选页，由作者决定下一步。
4. 作者点击问题，正文定位当前引用，右栏同时展示历史来源；读取引用所绑定的版本，不用最新正文替换历史证据。
5. 有确定冲突时，提供“修订候选稿”；没有确定冲突、但仍有待核查或风格意见时，作者填写处理理由后批准。
6. 批准后刷新正式稿、项目版本、候选有效性和记忆状态；下一章使用被批准的正文。

“自动修订一次”为明确的可选项，默认关闭。它可能增加模型请求，仍受同一任务预算限制；更多修订由作者发起新任务。

### 正文编辑边界

现有作者手工入口可以替换正式稿，并通过版本校验创建新正式版本。UI 使用“编辑正式稿 → 预览差异 → 保存为新版本”，保存前提示相关记忆将失效。草稿在本次编辑会话中保留，未保存离开时提醒；不能显示尚未实现的跨重启自动恢复承诺。

模型候选首版只读，可用文字要求让模型修订。直接手工编辑候选并保存为新候选，需要增加候选修订服务：新正文、新内容哈希、新提案及旧报告失效必须一致完成，随后重新审稿。这项能力列为后续扩展，不能调用正式稿替换接口绕过候选批准。

当前整章替换和整章模型修订不能绕过锁定段落。存在锁定时，引导使用局部改稿，或由作者显式解除锁定。

### 审稿与批准规则

| 条件 | UI 行为 | 服务端约束 |
| --- | --- | --- |
| 未完成审稿或事实提取 | “批准为正式稿”不可用；提供继续审稿入口 | 同一候选的有效报告必须齐全 |
| 存在 `conflict` | 显示“确定冲突”；不可批准 | 不能用作者理由跳过，须修订并重新审稿 |
| 仅存在 `uncertain/style` | 显示处理理由输入框 | 非空作者理由才可批准 |
| 报告与正文、哈希或项目基线不匹配 | 显示“候选已过期”；保留阅读和复制能力 | 重新准备候选，不能复用旧报告提交 |
| 提案已拒绝、被替代或所属运行已取消 | 只读展示历史状态 | 禁止再次批准 |
| 没有阻断项 | 提供明确的“批准为正式稿”按钮 | 最终在事务内重新校验，而非只信 UI 的可用状态 |

目前批准只存储一份作者 `reason`。首版提供统一理由；逐条“已处理”标记若要持久保存，需另补数据契约。不能把勾选 UI 当成核心已经支持的逐条豁免。

引用跳转保持原始正文及 UTF-16 位置不变；正文格式与作者标点不受 UI 文案规范自动改写。引用加载失败时显示“证据无法定位”，不能高亮一个相似段落冒充原句。

## 4 局部改稿

这是旧章修改入口。作者先选择修改起点并描述要求，例如“把林舟得知父亲身份的时间推迟到第六章”。

界面分为修改组列表、正文差异、影响与下一步。显示已检查和未检查的具体章节，以及直接冲突与待判断的因果影响；“未检查”不等于“没有影响”。

1. 分析完成后按组预览。组是最小选择单位，不能在界面中任意勾选单个字句后沿用原组结论。
2. 选择存在依赖的组时列出依赖，提供“同时选择依赖组”；未补齐依赖时不能继续。重叠修改与过期来源明确报错。
3. 点击“生成所选候选”执行现有本地 `select`，生成实际所选内容的候选集合。这一步不调用模型，也不改正式稿。
4. 每个受影响章节都要重新审稿；审稿输入是这些候选合成的整本书视图。UI 显示“已审稿 1／2 章”等实际计数，不能借用完整方案的旧报告。
5. 全部满足批准条件后，作者一次批准所选方案；任一章节失败都不能先写入其余章节。未选余项需要在新基线上重新分析。
6. 撤回采用新版本恢复原文。存在后续改动或新锁定时，展示阻断原因，禁止覆盖作者之后的工作。

已有锁定对应非空文本行区块。首版提供“锁定此段”，清楚展示范围；任意字符选区锁定没有现成入口。差异同时用颜色、加减号和前后列名表达，锁定文字在两侧保持一致。

## 5 故事记忆与上下文

记忆页按“事实、角色误信、未来计划、章节摘要”分组。人物、关系和章节来源作为筛选条件；右侧显示原句、来源版本、故事时间、角色获知时间及确认操作。

必须独立呈现四类信息：

| 维度 | 展示方式 |
| --- | --- |
| 信息类型 | 已发生事实、角色误信、未来计划；章节摘要单独分组 |
| 作者确认 | 待确认或已确认；历史确认不覆盖来源失效 |
| 来源状态 | 候选来源、当前有效、已失效 |
| 本次上下文选择 | 是否被指定章节实际采用，以及采用或省略原因 |

`memory status` 中的 `usedInContext` 只是“有效且已确认”的资格判断。UI 不能直接把它标为“本章已采用”；实际选择应读取该次 `ContextSnapshot.sources`，同时展示相关性、披露范围和预算限制。当前页面的预览和某次运行保存的输入快照也要分开。

未确认信息、失效信息和未批准候选事实不能作为有效确认事实送入后续写作。确认候选事实并不批准候选正文；确认或纠正正式来源的信息会更新项目版本，UI 应提醒当前候选可能过期，并刷新状态。

故事时间与角色获知时间分别展示，缺少证据显示“未知”。不能按第几章自动画出确定的故事时间轴，也不能把“作者知道”当成“角色已经知道”。

失效来源提供“查看原文”和“重建失效来源”。重建是模型任务，开始前展示预算。当前替换旧稿、重排章节或修改约束可能使全部已有有效派生记忆失效；页面统计以核心返回为准，不能只凭被编辑章节推断失效范围。

本阶段不增加任意关系类型、人物卡全字段编辑或自动真伪评分。纠正信息仍保留原来源与旧记录，不把用户输入包装成没有来源的新权威事实。

## 6 任务记录与模型设置

任务记录默认显示任务类型、章节、真实状态、当前已知步骤、请求次数与预算。展开后可看输入来源、返回产物、usage 和费用估算；模型原始提示词、原始响应与内部 ID 放入诊断详情。

- 同书已有模型写任务时，显示正在执行的任务并提供跳转和取消；首版不提供未实现的自动排队和多章并发。
- 当前没有 token 流式输出或精确完成百分比。运行中显示实际步骤和等待状态，不播放假的逐字生成效果。
- 浏览器关闭不等于取消后台任务；重新打开后按持久化运行查询状态。服务进程中断后的恢复仍沿用租约与所有权校验。
- `unknown` 属于单次模型请求状态，可与任务失败或取消同时存在。显示“结果未知，可能已产生用量”，不自动重发；显式重试继续受原预算限制。
- “恢复任务”和“只读重放”分开。重放只核对保存的数据，不是重新执行，也不表示原任务或创作质量通过。
- 没有 usage 或价格时费用显示“未知”；有完整输入时显示“估算费用”。上下文和预留预算的保守估算不能标为供应商实测 token。
- 离线配置检查和真实模型探测分开。模型探测按钮明确提示将调用服务；真实凭据只在服务端通过环境变量读取。
- 首版模型设置展示脱敏后的配置来源、模型和可用状态；任务预算可编辑。可视化修改供应商配置文件和密钥管理单独评估，避免把密钥存到浏览器。

真实模型效果与人工评测当前仍未通过验收。可在任务记录的高级入口查看评测条件；首版首页不显示没有依据的“小说质量分”或“效率提升”。

## 7 视觉与交互规范

使用暖白阅读面、深墨绿色导航及操作色、低饱和琥珀色提示与红色冲突。界面用中文无衬线字体，小说正文可使用宋体；正文行高约 1.8，优先阅读舒适度。

| 元素 | 设计约定 |
| --- | --- |
| 底色 | `#F6F5F1`；正文阅读面使用白色 |
| 主操作 | `#31594D`；同一区域只突出一个下一步 |
| 正文 | `#242C2A`；段落留白优先于装饰 |
| 状态 | 文本与图标共同表达；不用颜色单独区分 |
| 表单错误 | 就近解释原因，保留作者已输入的内容 |
| 可访问性 | 正文和操作文字以 AA 对比度为实现目标；键盘可定位问题与操作按钮 |
| 中文文案 | UI 渲染层处理中文标点与中英间距，文件路径、代码及作者正文保持原样 |

首次空工作区提供“新建计划”和“导入已有稿件”；缺少模型配置时，仍可阅读、导入、手工编辑与导出。网络或服务断开时保留页面已读内容，停用提交动作并显示连接状态。没有审稿问题时显示“本次审稿未发现问题”，不等同于质量保证。

## 8 推荐落地方式与接入缺口

推荐 React、TypeScript 和 Vite 构建本地 Web 界面，由本地 Node.js 服务调用现有核心。保持单仓库、单包和单锁文件；暂不引入桌面壳和独立云后端。选择理由是可以继续使用现有 SQLite 驱动、模型网关和恢复机制，同时将工作量集中在作者流程。这里是架构建议，本轮没有安装前端依赖，依赖维护与兼容性在实施前核查。

前端负责展示、表单和阅读交互；本地服务负责验证、业务调用与任务管理；SQLite 继续作为权威数据源。前端不直接操作数据库，也不通过拼接 shell 命令运行 CLI。

现有核心可以复用，但还需要完成以下接入工作：

| 缺口 | 需要补的接口或行为 |
| --- | --- |
| 稳定查询接口 | 汇总章节、候选正文、审稿、提取结果、历史和来源；补充筛选与分页，避免把数据库行直接作为公开契约 |
| 统一业务入口 | 将 CLI 中分散的查询与组装逻辑收敛到 application 层；HTTP 与 CLI 共用提交、锁定和预算规则 |
| 可解释的可用操作 | 提供只读的批准条件与阻断原因；不能为刷新页面调用会变更运行状态的校验函数；提交仍重新检查 |
| 异步任务启动 | 现有多数工作流返回完整结果；UI 需要启动即返回稳定 `runId`，并在后台继续执行，刷新页面不重复启动 |
| 状态与错误契约 | 定义可识别的状态冲突、锁定、预算和证据错误；前端不解析中文错误字符串判断业务 |
| 文件与工作区接入 | 浏览器上传保留原始字节、先预览再导入；服务端限制在显式注册工作区内；最近作品登记属于新接入能力 |
| 作者工作副本 | 正式稿手工编辑可复用 replace；可恢复草稿及手工修改候选须另设计，不能假定已有 |
| 浏览器安全边界 | 默认监听本机回环地址，校验 Origin 和会话凭证；不接受任意文件系统路径，不把供应商密钥返回前端 |

首版运行状态可在任务活跃时轮询，完成后停止。SSE、完整任务事件流和 token 流式生成按实际需要后置。必须先完成任务启动与重连契约，不能让 HTTP 超时或刷新页面变成自动重发模型请求。

## 9 施工顺序与验收

以下是建议的 UI 实施顺序，本轮交付范围仅为设计和概念图。

| 阶段 | 交付范围 | 可验证的完成标准 |
| --- | --- | --- |
| UI-1 创作闭环 | 本地服务和任务接口；作品入口、规划、章节阅读、审稿批准、基础版本导出、任务恢复和只读模型配置 | 用固定响应从三章计划走到逐章批准与导出；刷新页面不丢任务，不产生额外请求 |
| UI-2 记忆可解释性 | 记忆筛选、来源定位、确认纠正、别名、作者约束、实际上下文预览和失效重建 | 未确认、未批准和失效来源不能被显示为本次已采用；确认正式来源后候选有效性正确刷新 |
| UI-3 安全改稿 | 影响范围、修改组依赖、实际差异、段落锁定、逐章再审和撤回预览 | 三组选两组后重新审稿；缺依赖或触碰锁定被拒绝；撤回不覆盖后续编辑 |

接入验收重点：

1. 候选未经批准不出现在正式导出和后续写作输入中；确定冲突无法通过按钮、快捷键或直接接口绕过。
2. 内容或基线变化后，旧报告不能继续批准；冲突时保留作者输入并给出重新加载入口。
3. 双标签页提交同一候选或启动同书任务时，正式版本和请求数不重复增加。
4. 请求在途时关闭页面、服务中断、恢复以及显式取消，均保持既有 unknown、预算与所有权规则。
5. 部分改稿真实选择与差异一致，多章全部审稿合格后原子批准；来源中不得混入未选内容。
6. 证据定位覆盖重复原句、中文、emoji 和 UTF-16 偏移；定位失败明确报错。
7. 长章阅读、窄窗口右栏、键盘操作和 UI 文案排版通过实际浏览器检查；正文内容不被自动排版逻辑修改。
8. 费用未知保持未知；页面不默认触发模型请求；密钥与原始配置不进入客户端错误信息。

实现后的验证应包含现有必要检查、HTTP 契约测试及关键浏览器流程。概念图只验证布局意图和状态表达，不代表这些交互已经完成。

## 10 概念图与设计依据

### 章节工作台

[章节工作台概念图](concepts/01-chapter-workbench.png)：候选正文占主要空间，问题与历史证据并排可核对。示例存在确定冲突，因此“批准为正式稿”保持禁用。

### 局部改稿

[局部改稿概念图](concepts/02-local-revision.png)：两组选中、一组未选，依赖、锁定段落和未检查范围可见。主操作只生成实际选择的候选。

### 故事记忆

[故事记忆概念图](concepts/03-story-memory.png)：作者确认与来源状态分列。下方显示实际上下文来源清单；选中的未确认信息没有被采用。图中的“2 条来源已失效”为简化提示，实际产品应分别统计来源章节和受影响条目。

### 作品入口与导入

[作品入口与导入概念图](concepts/04-library-import.png)：显示最近主动打开的作品；选中文件后先预览编码、拆章和重复检查结果，再确认写入。

### 章节规划

[章节规划概念图](concepts/05-chapter-planning.png)：左侧选择本批章节，中间编辑目标、视角、事件和约束，右侧核对作者约束；保存后显式批准整批计划。

### 任务记录与恢复

[任务记录与恢复概念图](concepts/06-task-records.png)：展示中断任务的已保存步骤、未知请求、预算预留与未知费用；重试需要明确确认，并与只读重放区分。

### 版本与导出

[版本与导出概念图](concepts/07-versions-export.png)：区分当前版本与选中的历史快照，预览历史正文并导出指定版本；恢复先预览，再创建新版本。

### 模型与设置

[模型与设置概念图](concepts/08-model-settings.png)：展示只读模型配置、下一次任务预算、离线检查及独立的模型探测；示例凭据未配置，探测按钮禁用。
