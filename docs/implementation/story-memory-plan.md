# 小说记忆系统执行计划

目标是让续写、审稿与改稿基于指定稿件版本，正确区分故事事实、人物认知、读者已知信息与未来计划，并能追溯每项判断的来源。先完成小说领域规则，再验证 Hindsight 的检索收益。

基线为 `0194ecd`。当前已具备 M0～M7 核心与八页工作台；基线工程结果为 119 项离线测试及 10 项浏览器流程通过，详见 [工作台验收记录](workbench-acceptance.md)。用户已授权按本计划实施，阶段状态和实际验证随执行更新。

## 范围与实施原则

- 保持单用户、本地工作台与现有 CLI，继续使用 TypeScript、SQLite、Zod 和现有模型网关；不同时迁移 Agent 编排框架。
- 正式正文、已批准计划、作者设定、确认与纠正记录属于权威数据。抽取结果、摘要、人物状态投影和检索索引都绑定来源与构建版本。
- 一部作品共享同一套数据，各 Agent 和人物通过不同视图读取；不为每个人物复制独立的事实库。
- 场景用于上下文与生成步骤，章仍是正文批准、历史版本和导出的主要单位。候选场景只在所属运行内流转。
- Hindsight 是首选待验证的检索适配，不接管正文与审批。它增加本地服务和 PostgreSQL；中文配置、预算与恢复门槛通过后才允许启用。
- 首版不增加任意剧情分支、多人协作、全书自动批准、跨作品自动共享记忆、自动修改模型权重或无限 Agent 自循环。
- 按 N1～N8 顺序推进，每阶段先完成对应回归与必要检查，再进入下一阶段。工程结果与模型效果分别记录。
- N1～N8 的实现、项目内依赖和迁移按本次执行授权推进；真实模型验收使用已明确的配置与预算，缺少凭据或人工标签时如实保留待验证。Git 提交与推送仍依据明确授权；这份计划不创建 Goal，也不派发子 Agent。

## 必须固定的领域语义

### 记忆类型与来源

| 类型 | 保存内容 | 提交与使用条件 |
| --- | --- | --- |
| 作者设定 | 世界规则、人物身份、能力限制、公开与秘密设定 | 版本化作者决定；与正文冲突时列出冲突，不按“最新输入”静默覆盖 |
| 事件与断言 | 发生的事件、人物关系、地点、物品及状态变化 | 区分客观断言、人物言语、传闻、梦境和推测；原文出现不等于结论真实 |
| 人物认知 | 知道、相信、怀疑、听说及误信的形成与变化 | 记录持有人、命题、获知事件与依据；不能由“同场出现”自动推定全部角色知情 |
| 叙事披露 | 读者在何处接触线索、确认真相，允许本场景披露什么 | 已发生的披露与计划中的披露分别保存；不能将作者知道等同于读者知道 |
| 剧情计划与伏笔 | 待推进事件、承诺、埋设、揭示、回收与放弃决定 | 计划不进入已发生事实；实际埋设和回收需正文来源，长期未提及不等于可遗忘 |
| 正文与摘要 | 不可变原文、场景与章节摘要、状态汇总 | 摘要保留所有来源依赖与可见范围；不得因压缩把秘密并入可公开内容 |
| 风格与经验 | 作品语气、人物表达、作者采纳的编辑反馈 | 与剧情断言分开；只使用显式确定的作品规则，不做跨作品自动学习 |

正文证据继续使用 `chapterId`、`revisionId`、`blockId`、原文哈希与 UTF-16 范围。作者设定引用作者决定版本，计划引用已批准计划版本，不伪造不存在的正文引用。

确认状态、来源有效性、内容种类和实际采用状态分别表示。确认一条误信只表示准确记录了该人物的想法，不把它升级为世界事实。模型置信度不能代替作者确认或引用检查。

### 四个独立坐标

| 坐标 | 首版表达方式 | 禁止推断 |
| --- | --- | --- |
| 故事时间 | 事件锚点、先后关系与有效区间；不能比较时返回 `unknown` | 不把章号、入库时间当作故事发生时间，不强行生成日历日期 |
| 叙事位置 | 稳定场景 ID、场景修订和当前快照中的排列位置 | 重排只改变叙述位置，不自动改变事件先后 |
| 获知位置 | 人物认知变化引用获知事件，必要时记录认知失效或修正 | 没有证据时保留未知，不推定角色必然知道或绝不知情 |
| 稿件版本 | 当前项目快照及不可变正文、计划、规则修订 | 不用旧稿的更高检索分数覆盖当前稿 |

场景 ID 与显示序号分离，正文区间绑定具体修订。场景边界改变时必须重新定位和验证引用。相对事件关系使用有限的可比较规则，拒绝循环、悬空引用和明确矛盾区间。

### Agent 的读取契约

任务请求至少确定作品快照、任务类型、目标场景、视角人物、叙述方式和故事位置。任务类型由工作流确定，不能由模型自行提升读取范围。

| Agent | 默认读取范围 | 返回结果与约束 |
| --- | --- | --- |
| Planner | 作者设定、当前正式故事状态、已有计划、开放伏笔及全局秘密 | 场景计划与披露安排；未来事件始终保持计划类型 |
| Writer | 本场景目标、可使用的角色认知、允许披露的事件、相关风格规则及安全的伏笔要求 | 场景候选；不直接接收未筛选的全局秘密、审稿内部材料和完整历史索引结果 |
| Reviewer | 被审候选、完整相关事实、人物认知和披露规则、原文证据 | 区分事实冲突、角色越界知情、提前披露与待核查问题 |
| Extractor | 指定正文修订及必要的身份字典 | 有来源的事件与记忆变更候选；不借大纲补全正文未发生的信息 |
| 改稿分析 | 修改点、来源依赖、相关正式场景、约束与披露安排 | 明确检查范围和受影响项；不能宣称覆盖未检查的内容 |

首版支持有限视角、全知叙述和不可靠叙述三种配置。有限视角需要人物身份；不可靠叙述保留说话者／叙述者归属；全知叙述仍受读者披露计划约束。回忆体等需要明确叙述者的知情位置，不能自动套用当前人物的故事时刻。

明确批准本场景揭示的事实，可以标为“在本场景获知”的写作目标，不能因此认为人物在场景开始前已经知道；实际认知仍以正文来源和作者采纳为准。

过滤覆盖事实、摘要、原文片段、修订指令和审稿反馈。任务目标、作者约束与伏笔说明也须生成适合当前任务的视图，不能通过这些入口把全局秘密原样拼入 Writer。不能只过滤事实 ID，却把包含秘密的整章原文或 Reviewer 建议交给 Writer。混合可见性片段须选择可核对的原文范围，或省略并记录原因；不靠自由改写伪装成原文。

### 候选与正式状态

```text
已批准设定和正文快照
    → 按场景构建上下文
    → 生成场景候选与任务内记忆
    → 拼接实际章节候选
    → 整章审稿、来源校验和记忆变更预览
    → 作者批准
    → SQLite 同事务保存新版本、作者决定、失效标记和待同步任务
    → 事务外重建摘要与检索索引
```

同一章后续场景可以读取本次运行中较早场景的候选变化，但这些变化不得进入其他运行的正式上下文。修订早期场景后，依赖它的后续候选步骤必须重新检查，不能继续复用旧结果。

章节批准与记忆确认保持独立记录。未确认的模型断言不得作为权威事实；已批准正文可以在满足场景可见范围的情况下作为原文证据。界面以章级变更预览降低处理成本，身份、知情、关键因果和伏笔变化重点核对。

### N1 领域契约与固定验收材料

目标：先固定“什么可以被当作事实、谁在何时能使用”，避免不同 Agent 各自解释规则。

范围与入口：`src/domain/`、`src/context/memory.ts`、`src/domain/review.ts`；新增 `fixtures/story-memory/` 和对应纯规则测试。新目录仅放人工可阅读的虚构故事、场景标识、版本变化及期望结果，不放真实稿件或凭据。

工作：

1. 用 Zod 定义场景、事件关系、带归属的断言、人物认知变化、披露记录和伏笔状态；统一来源联合类型与独立状态字段。
2. 定义目标场景的读取请求、返回清单与省略原因；未确定时间不能被强制排序，未知知情不能被当作确定冲突。
3. 建立至少 12 个边界场景，覆盖下文验收矩阵；材料明确标注为工程合成样例。
4. 记录规则版本和各 Agent 可见范围；不增加通用插件注册器、任意知识图谱 DSL 或 Agent 框架。

验收：非法身份、缺失来源、循环事件关系、错误确认状态和不完整有限视角配置被拒绝；误信、计划和世界事实能同时存在。示例中的读者已知真相不使视角人物自动知情。

### N2 持久化与旧数据兼容

目标：让场景、认知和披露信息与正文版本一起可追溯，并保护已有作品。

范围与入口：`src/storage/database.ts`、`book-store.ts`、`memory-store.ts`、`src/application/` 及 CLI／本地动作接口；本阶段实施时才新增数据库迁移。

工作：

1. 为人物分配稳定身份，保留原名称与别名；同名不能自动合并，旧字符串身份建立可检查映射。
2. 场景及其正文区间、作者决定、已批准计划引用进入版本快照；持久化知情与披露变更，保留纠正链。
3. 旧章节没有场景标注时建立一个章级场景，未知时间和叙述方式继续未知；不得迁移成“全知”或“所有角色已知”。通过旧格式解码与新增记录完成兼容，不重写不可变的正文或历史快照。
4. 提供场景与作者决定的最小新增、查看、编辑、确认操作，写入必须携带版本并经过统一提交服务。
5. 迁移前验证工作区备份可恢复；只在副本验证升级、事务回滚、未知高版本拒绝和重复执行。旧快照导出保持原结果。

验收：当前工作区副本升级后正文、章节顺序、锁定与历史导出一致；迁移失败不留下部分新状态。旧运行和上下文保留协议版本，恢复沿用已保存输入，不用新规则重新解释旧产物。

### N3 场景上下文与读取规则

目标：获得可解释、可重放的 Agent 输入，检索相关性不能覆盖信息可用性。

范围与入口：`src/context/builder.ts`、`memory.ts`、`selection.ts`、`src/review/evidence.ts` 与上下文查询接口。

工作：

1. 根据目标快照、故事位置、视角和披露计划计算可用来源；保留当前原文定位和版本检查。
2. 硬约束、本场景目标、必要人物状态及到期伏笔优先进入上下文；其他信息按本地检索与剩余预算选择。
3. 分别生成 Planner、Writer、Reviewer、Extractor 和改稿分析视图。Planner 补入已有正式故事及计划，Writer 不复用 Reviewer 的全局视图。
4. 原文、摘要与模型返回的引用都执行相同范围检查；未知项进入有标记的待核对清单，不伪装为确定知识。
5. 保存上下文协议版本、选择规则版本、来源修订、选择与省略原因以及预算估计。普通查询和页面加载只运行本地逻辑，不隐式请求 Embedding 或模型。

验收：固定集合中的旧版本、其他作品、不属于本次运行临时视图的未批准候选，以及已明确禁止披露的来源进入 Writer 输入的数量为零；含秘密的摘要与原文同样被排除。硬约束超预算时明确失败，不能为了填满上下文使用被拒绝来源。

边界：这里验证的是可确定的输入规则；正文是否在语义上泄露秘密，仍需 N4 审稿和 N8 人工效果评测。

实现决定：新规则使用独立的 `story-v1` 上下文协议，旧运行保留原输入。Writer 只读取显式场景指令、标为 Writer 可见的规则、可用断言与经定位核对的引用片段；没有范围标注的整章和旧摘要默认省略。对已知禁用命题的字面内容再做保守阻断，但不能据此证明开放文本的语义无泄露。混有秘密的全局硬约束必须由作者改为适合当前场景的规则，不能静默截去后继续。Reviewer 的全局反馈不直接转交 Writer，自动修订重新按各场景范围生成。

### N4 创作工作流与记忆变更闭环

目标：让新的记忆规则实际参与创作，而不止用于展示。

范围与入口：`src/workflows/creation.ts`、`memory.ts`、`impact.ts`、`src/application/proposals.ts`、`src/proposals/patches.ts`、`src/llm/tracked-gateway.ts` 与 `prompts/`。

工作：

1. Planner 返回场景目标、叙述方式、视角、故事位置、披露与伏笔要求；计划修改仍产生新提案。
2. Writer 在同一运行中顺序生成场景，持久化各步输入、候选与临时记忆；整个运行共享预算，不能按场景重置额度。
3. 拼接实际章稿后统一审稿与抽取，检查跨场景衔接、事实矛盾、角色知情和披露范围。修订只使用适合 Writer 的反馈视图。
4. 抽取产生带来源的记忆变更候选，作者确认不改变内容种类；不把角色说谎、梦境或未实现计划写成世界事实。
5. 任务开始保存基线，检索与上下文形成独立的持久化步骤；恢复复用实际保存的清单，基线改变则拒绝旧运行继续写入。
6. 部分改稿只对实际选择后的章稿审稿与提取；未选中的变化、旧报告、旧场景候选不得进入批准事务。

验收：完成规划、场景生成、整章审稿、作者处理和正式提交；在场景之间中断能恢复，拒绝与取消不污染正式记忆。早期场景修订、未知请求、截断响应和多章部分采纳分别有回归。

实现决定：已启用故事状态的作品使用场景规划协议；旧作品保留原章级协议。场景临时记忆只包含同一运行、相同叙述方式与视角、可比较在前的候选片段，并再次检查目标场景范围；未提供跨视角候选的自动知识转移。修改早期场景时整章场景重生成为新候选，不复用旧的下游候选。正文批准只绑定场景范围；作者另外采纳章级记忆变更，再确认断言。抽取器不能创建作者决定、覆盖纠正链或自行确认。

### N5 来源依赖与增量重建

目标：改稿后准确停止使用受影响信息，并保持重建与正式提交之间的一致性。

范围与入口：`src/storage/book-store.ts`、`memory-store.ts`、`src/application/workspace.ts`、`src/workflows/memory.ts`、运行仓储及待同步任务仓储。

工作：

1. 派生条目记录正文、事实、作者决定、场景位置与规则版本依赖；按需要记录，不预建通用图数据库。
2. 正文、约束、事件顺序、获知或披露位置改变时，在同一事务内推进项目版本并标记相应派生条目失效。依赖不完整时保守失效，不能冒充精确命中。
3. 追加保留未变来源；重排重新核对叙事披露和顺序相关摘要；旧章修改重建相关条目与其下游汇总。
4. 作者纠正与放弃决定保留追溯，重建不得复活已废弃的抽取结论，也不能把旧纠正静默套到新的正文来源。
5. 本地提交事务只记录待同步任务，外部索引写入在事务外执行。任务绑定来源修订、内容哈希和操作身份，支持查询、失败恢复与已完成结果复用。
6. 索引滞后时依据本地快照排除旧内容，回退到符合可见范围且预算允许的正式原文；材料不足时明确报告。

验收：追加、替换、插入、重排、纠正、恢复和撤回的失效集合符合预期；正文提交后立即崩溃仍能看到正确失效状态。重复同步不重复提升正式状态，迟到结果不能替换新版本。

### N6 工作台与作者操作

目标：作者能理解记忆为什么被采用，并能修改错误的时间、归属和披露安排。

范围与入口：`web/pages/Planning.tsx`、`Chapters.tsx`、`Memory.tsx`、`Patches.tsx`、`Runs.tsx`、`Settings.tsx` 和工作台查询／动作接口。沿用现有视觉，不新增独立仪表盘或全面重做八页。

工作：

1. 规划页编辑场景、视角、事件位置及披露要求；未明确的必要字段可见，不静默采用宽松默认值。
2. 记忆页增加事件、人物认知、披露与伏笔视图，展示对应正文或作者决定；确认、来源、内容种类与采用状态分别显示。
3. 章节页展示本次 Writer 实际上下文和记忆变更，允许按章批量处理，突出身份、知情及关键因果变化。
4. 改稿页展示受影响的记忆与来源；任务页显示重建／同步状态；设置页仅显示已接入服务的真实配置与检查结果。
5. 保留版本冲突、未保存提醒、键盘操作和窄窗口访问能力。普通浏览不启动收费检索。

验收：浏览器走通“误信保留、真相延迟揭示、改稿移动获知位置、确认与撤回”的闭环；错误路径保留用户输入，过期操作不能覆盖新数据。

### N7 Hindsight 接入与准入检查

目标：验证中文长篇召回收益，同时让外部服务失效不会破坏正文或放宽读取规则。

范围与入口：现有上下文与同步接口，加一个 Hindsight 适配模块和测试替身；部署说明放 `docs/implementation/`，若需要服务配置则单独确定 `infra/memory/` 目录约定后创建。单包与单锁文件继续保留。

工作：

1. 重新核对稳定版本、许可证、维护活动、TypeScript 客户端、部署要求及中文支持；调研基线 `v1.1.0` 不等于届时自动采用的最新版本。
2. 使用独立临时作品验证本地服务。配置中文适用的 Embedding、重排与全文检索；核实 PGroonga 等扩展的部署要求，不把默认英文配置或“支持多语言”的说明当成效果证明。
3. 每部作品使用独立命名空间，外部文档 ID 含不可变正文修订与来源身份。默认不按同一个章节 ID 覆盖历史内容，不向默认共享库混写多部作品。
4. 适配器接收允许的来源集合，返回来源 ID、分数和诊断；应用从 SQLite 解析原文并复验全部依赖。服务生成的记忆文本、反思或综合结论不能直接作为权威事实注入。
5. 普通上下文预览保持离线。付费语义检索只作为显式创作／重建任务的一步，查询、结果与原文清单保存后可只读重放。
6. 对齐 SDK、服务工作线程和模型客户端的重试与取消行为；覆盖抽取、Embedding、重排、后台整合等所有内部调用。检索深度和返回 token 上限不是费用预算。
7. 记录外部操作 ID；未知结果先查询状态，不能因为文档 ID 支持去重就认为重新提交不再收费。无法观测或限制内部调用时，禁止作为正式默认路径启用。
8. 检查初始化、维度探测、遥测和后台任务是否发起额外请求；普通测试、模块导入和离线检查继续禁止外部网络。

准入条件：持久化重启、作品隔离、来源版本、中文查询、取消、断网、结果未知、内部重试预算和旧索引回退测试全部通过。时间查询结果必须再执行本地范围判断，不能依赖服务的时间排序来防止提前披露。

未满足准入条件时保留本地读取路径，并在 ROADMAP 记录未通过的具体条件；适配契约测试通过不代表真实服务已验收。

### N8 对照评测与完整交付

目标：分别回答规则是否正确、记忆召回是否改善、实际修稿是否更省力。

工作：

1. 保留 N0 原始基线记录，对比“新领域规则加本地检索”与“相同规则加 Hindsight”；相同模型、材料、任务和预算策略，避免把规则改进归功于检索组件。
2. 准备人工可核对的中文材料、开发集和留出集，覆盖线性与倒叙、别名、误信、秘密、长期伏笔和多次改稿。合成材料只计入工程回归。
3. 在摸底后、留出评测前冻结指标和阈值。沿用现有评测协议至少每组每任务 3 次独立运行，并扩展记忆检索指标，不覆盖原协议或伪造人工标签。
4. 记录来源召回与精度、原文引用有效率、旧版本误用、未允许披露的输入、正文提前揭示、作者修稿时间、延迟及全部调用费用；输入过滤正确率与正文语义质量分别报告。
5. 完成 CLI、接口、浏览器、历史导出、锁定、部分采纳、撤回与恢复回归；真实服务和真实模型测试使用独立入口及固定预算。
6. 更新当前使用说明、迁移与备份说明、服务启动／停止与故障回退说明、测试证据和剩余限制，清理本轮可重建产物。

工程硬门槛：固定回归集中的失效或跨作品来源混入、未批准候选进入正式上下文或其他运行、明确禁止披露的输入混入、无效引用被接受、重复正式提交与未批准锁定修改均为零。不能据此承诺开放文本的语义泄露率为零。

效果门槛：人工参考标签与阈值冻结后才能判定；缺少模型凭据、完整费用或人工结果时，分别保留为待验证，N8 整体验收不得标记完成。若 Hindsight 没有形成稳定收益，不将其设为默认依赖。

## 关键验收矩阵

| 编号 | 场景 | 预期结果 | 首次覆盖阶段 |
| --- | --- | --- | --- |
| C01 | 作者确定真凶，人物误信另一人，读者提前知道 | 三种信息并存；有限视角沿用该人物认知，不把误信判为世界事实 | N1／N3 |
| C02 | 第 8 章倒叙到事件之前 | 状态按故事位置判断，不能使用第 7 章已披露但尚未发生的变化 | N1／N3 |
| C03 | 人物同场但没有目击或获知证据 | 不自动新增知情；未知不等于断定不知情 | N1／N4 |
| C04 | 一段原文或摘要同时包含可用信息与秘密 | 不整体绕过范围检查；返回可核对片段或省略原因 | N3 |
| C05 | 同名角色、多个别名与别名纠正 | 稳定身份不被自动误合并，相关选择结果重新核对 | N2／N5 |
| C06 | 台词撒谎、传闻、梦境与不可靠叙述 | 保留归属与类型，确认后也不自动变为客观事实 | N1／N4 |
| C07 | 很久前的伏笔到本场景应回收 | 从计划与开放事项中必选，不因时间久或语义分数低遗漏 | N3／N4 |
| C08 | 两个角色持有不同物品，单值状态出现时间冲突 | 多值正常共存；单值冲突只有明确重叠依据时才确定报告 | N1／N3 |
| C09 | 早期场景修订、三组改稿只选两组 | 后续候选依赖重新检查；未选内容及其记忆不能提交 | N4／N5 |
| C10 | 移动获知场景、重排、恢复旧稿与撤回 | 重新核对认知与披露，保留历史版本，旧事实不能误入当前上下文 | N5／N6 |
| C11 | 提交后重建前退出，索引服务断开或返回迟到结果 | 本地状态一致，旧结果被拒绝，允许来源范围内回退 | N5／N7 |
| C12 | 请求超时未知、重复入库、预算用尽、初始化或后台重试 | 状态与费用保留；无隐式重发、预算重置或未记录的模型请求 | N4／N7 |
| C13 | 旧数据库升级失败、旧运行恢复、旧快照导出 | 迁移回滚，正文与历史可读，旧协议结果不按新规则重新解释 | N2／N8 |
| C14 | 硬约束超预算，来源哈希错误或服务返回假 ID | 明确失败或拒绝该来源，不截断硬约束、不把失败标为成功 | N3／N7 |
